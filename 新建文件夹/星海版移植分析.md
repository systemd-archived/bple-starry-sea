# 星海版 → bp2 移植 分析报告

> 目标：把 `${桌面}\bp移植`（dnSpy 制作的"星海版"模组）移植进 `bp2`（BPLE 2022.1.9 原始解编译工程），在 Unity/C# 源码里继续开发。
> 本次交付：**分析与方案**（未改任何代码）。

---

## 一、总体结论（已确认）

1. **bp2 是原始基线**，模组源是 dnSpy 反编译的修改版。
   - 证据：bp2 的 `DigitalDisplay.cs` 只显示一个十六进制位（原版）；模组端实现了「118 个自定义模式」。
2. **所有模组功能都是对现有类的修改**，没有新增游戏类。
   - 模组源里的 `ONLY-MOD` 文件（`--f__AnonymousType0.cs`、`-PrivateImplementationDetails*.cs`、`IEdge.2.cs`、`Variant.2.cs`、`System/.../RefSafetyRulesAttribute.cs`、`Microsoft/.../EmbeddedAttribute.cs`）**都是 dnSpy 生成的反编译噪音**，不代表新功能，不要移植。
3. **两种反编译风格差异巨大，无法直接 diff/整文件复制。**
   - dnSpy 风格：每行 `this.` 前缀、`global::` 前缀、`// Token: 0x...` 注释、迭代器拆成 `<Method>d__xx` 类、委托装箱、字段和方法带 RID/Offset 注释等。
   - bp2 风格：ILSpy 家族，`yield` 保留、`this.` 省略、无 token 注释。
   - 因此行数差异普遍 1.5~1.7 倍（如 `Balloon.cs` 266→447，`Achievements.cs` 36→49），**纯属风格噪音**。
4. **部分功能 bp2 已经内置/一致**（无需移植）。
   - `Balloon.cs`：bp2 与模组端逻辑完全一致（气球升力已按 `Physics.gravity` 缩放）。星海版.txt 里那句"重力-9.81 为原版 / 重力 0 无升力"在原始逻辑里就已满足。
   - → 这类文件在移植时**跳过**，避免重复改动。
5. 模组运行时部署目录（游戏本体）存在：`C:\Users\Administrator\Desktop\新创Unity 内测版—修改2022.1.9 Windows 64-bit`。

## 二、推荐移植方法论（关键）

由于风格噪音，**最可靠、最可持续**的迁法：

### 首选：用同一反编译器 clean「双 dll」对比
1. 安装 ILSpy CLI：`dotnet tool install --global ilspycmd`（若系统有 dotnet；当前机器未检出，需先装 .NET SDK）。
2. 用 `ilspycmd` 反编译两个 dll 到两个独立目录：
   - `bpdll\Assembly-CSharp.dll`（**原始**）→ `orig/`
   - `bpdll\Assembly-CSharp(修改).dll`（**星海版**）→ `mod/`
3. 删掉反编译噪音文件（`--f__AnonymousType0`、`-PrivateImplementationDetails*`、`IEdge.2`、`Variant.2`、`RefSafetyRulesAttribute`、`EmbeddedAttribute`）。
4. 对两个目录做 `git diff --no-index orig mod`（或文件夹对比工具）。
5. **得到的 diff 就是星海版的纯语义改动**，逐文件应用到 bp2 源码即可，干净且不会误伤。

> 前提校验：确认 `bpdll\Assembly-CSharp.dll`（原始）与 bp2 源码是**同一构建**（"科技版" 与 "BPLE 2022.1.9"）。若两者在非模组文件上也有差异，说明底版不同，需以它们为准做一次基础对齐。当前证据表明二者同底。

### 次选：人工语义比对
若无法装反编译器，则不整文件替换，而是**逐类逐方法**读模组源实现 → 手工改写进 bp2 对应类。工作量大、易错，适合少量逻辑点。

## 四、复杂度分级与移植顺序建议

**Tier 1 — 低风险数值微调（先做，练手+快速见效）**
- 视野上下限（`IngameCamera.cs`/`INFeature.cs`）
- 光组件电量（PointLight 系列）
- 核拳连接距离（`BoxingGlove.cs`/`SpringBoxingGlove.cs`）
- 涡喷推力（`JetEngine.cs`/`Engine.cs`）

**Tier 2 — 中等：单点逻辑**
- 磁铁八向旋转、铰链板、框架、机炮子弹、拳套星级、车轮射线、气球（跳过）、承重伞、虚化蛋-菠萝、引力鸟蛋、油箱、火箭、零星发射器

**Tier 3 — 高风险：系统级交叉逻辑（放在最后、独立分支逐个提交）**
- TNT 全系（连锁/冲击波/定时/解保险）
- 切光机制
- 电路系统 / 压敏电阻 / 染色框倍率
- 数字显示器 118 模式（最大块）

**强烈建议**：每个功能一个提交/一个分支，改完即在 bp2 Unity 里编译 + 进游戏实测（尤其 TNT 和电路），不要一次性全量移植。

## 五、风险与注意

1. **噪音干扰**：不要迷信 `diff_results.txt` 的 "DIFF"（全部文件都标了，纯属风格噪音）。无意义。
2. **遗漏魔改逻辑**：模组某些改动可能隐藏在不显眼处（如 `Rigidbody.currentForce`、`Physics.gravity` 全局改重力、`Time.timeScale` 等）。移植时以「星海版.txt 逐条核对」+「clean diff 双 dll」双保险。
3. **依赖**：bp2 工程能否独立编译出模组所需依赖（`INSettings`、`INFeature` 枚举、`INUserSettings` 等 `IN*` 接口）需在 Unity 工程里确认——这些是游戏内置的"科技版"接口，bp2 若为同底应自带。
4. **编译环境**：需要能在 Unity/Tuanjie 里编译 bp2（AGENT.md 称 Windows 上可构建）。当前机器未检出 dotnet/反编译器，若走"clean diff"方案需先装 .NET SDK + ilspycmd。
5. **不要在 bp2 里浑水摸鱼**：只改本次功能相关类，不动无关代码。
